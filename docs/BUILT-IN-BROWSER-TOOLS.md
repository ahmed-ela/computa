# Built-in browser tools

Computa's `browser_*` tools operate its own WebKit human tabs without a Chrome connection. They share the existing signed-in browser profile. Model inference pages and the privileged app UI are excluded from inventory and binding. The website assistant requests operations; the local controller supplies current page observations and executes approved actions.

## Boundaries and composition

`EmbeddedBrowserTools` owns the strict public schemas. `EmbeddedBrowserToolController` owns turn contexts, explicit tab leases, bounded inventory continuations, published snapshots and cleanup. `EmbeddedBrowserActionReferences` maps published typed references to exact captured targets; the existing `BrowserTabSessionBroker` retains observation and one-use action authority. `EmbeddedBrowserControlBackend` is the narrow backend interface; `EmbeddedBrowserTabTransport` implements it for `EmbeddedBrowserSession`. A fixed script in a named isolated JavaScript world supplies main-frame DOM semantics and guarded semantic activation. Model callers cannot submit arbitrary JavaScript.

`CodexAppServerRuntime` advertises these schemas only after the app configures the controller. The runtime requires the exact active thread/turn, uses a unique runtime-generation/task/turn key, obtains existing native computer-use approval for mutations, and checks authority again after approval. The browser response does not pass through native-app action-reference rewriting. `AppState` configures the same browser session before loading the runtime.

The complete `thread/start` manifest uses the pinned App Server's canonical dynamic-function form: `type: "function"`, `name`, `description` and `inputSchema`. Browser and native tools must use that form consistently. An installed build 35 check found legacy browser entries mixed with canonical native entries, which prevented thread creation before website inference. Build 36 adds the missing canonical type and tests actual acceptance of the combined manifest by the pinned engine, alongside strict fixture parsing.

Browser mechanics are independent of the model provider, native window binding and command executor. A localhost development server started through terminal tools can be inspected through these browser tools. Fresh capability guidance is rebuilt from the current offered schemas on every website inference; a user need not name tools or explain the harness. Tool tabs and terminal sessions survive the separate [temporary website inference transactions](WEBSITE-INFERENCE-TRANSACTIONS.md) within their native turn.

The pinned runtime persists dynamic tool identities at thread creation. An older chat with no `browser_*` tools still needs a new chat to obtain them. For recognized native schemas, Computa refreshes the callable contract for each inference without replacing rollout metadata or adding an unregistered tool. New catalogs separate fresh `browser_read` from `browser_continue`; saved catalogs without the latter retain the legacy cursor-bearing read contract. Completed history accepts the exact v1 snapshot/index, v2 snapshot/index/role/label and v3 typed-reference forms, plus recognized prior read schemas; original tool identities and argument bytes stay unchanged. New calls use the strict contract supported by their admitted catalog. Custom or MCP schemas do not acquire this migration.

## Operations

| Tool | Main arguments | Result and scope |
| --- | --- | --- |
| `browser_tabs` | optional observed `cursor` | Bounded metadata page for human tabs; follow its opaque `next_cursor`. Metadata alone is not page-content evidence. |
| `browser_open` | explicit HTTP(S) `url` | Creates and binds a background task-owned tab using the shared profile. |
| `browser_bind` | currently issued `tab_id` | Leases an available observed human tab without activation or navigation. |
| `browser_navigate` | HTTP(S) `url` | Navigates the bound target once and retires the old action snapshot. |
| `browser_read` | optional `view`, literal `query` | Fresh bounded semantic selection, starting at page one; eligible published rows carry `click_ref` or `fill_ref`. No cursor is offered in new catalogs. |
| `browser_continue` | required observed `cursor` | Continue the latest page's exact selection with `next_cursor` alone. Null, omitted cursor and view/query arguments are rejected. |
| `browser_click` | current `click_ref` | One guarded semantic press; inspect the returned observation or read the changed page to verify the outcome. |
| `browser_fill` | current `fill_ref` and `text` | Replaces one observed editable value and sends input/change events. Fill is separate from submission; inspect the resulting value before pressing. |
| `browser_wait` | optional nonempty `text`, `timeout_ms` | Read-only event-driven readiness/text wait, bounded to 10 seconds. Does not refresh or repeat input. |
| `browser_close` | none | Releases the bound page; closes only the page created by this task. |

Inventory pages are at most 8 KiB, with explicit omitted/truncated metadata. Displayed titles are limited to 256 UTF-8 bytes at a scalar boundary; a single oversized combining-character grapheme cannot stall pagination, and JSON control-character escapes still fit the row budget. URLs longer than 2,048 UTF-8 bytes are omitted, never shortened into a different address. Inventory continuations retain metadata captured for that inventory; they are not fresh page-content observations. Cursors are opaque, one-use and confined to their originating turn. Only returned rows issue bind IDs, and binding rechecks the current exact target. Semantic reads reuse the broker's bounded views and pagination. Cursor-only continuation preserves already exposed action references from the same immutable capture within the unchanged 120-reference FIFO limit. Successful fresh reads publish new references and may corroborate earlier published targets under the checks below; only admitted published references can authorize input. Transcript text and indices cannot restore a retired capability.

## Ownership, actions and cleanup

New catalogs offer `browser_read(view?, query?)` for fresh selections and `browser_continue(cursor)` for page continuation. A fresh page read defaults to overview unless a view or query selects another default. Continuation requires the exact nonempty latest `next_cursor` and retains the captured filters. Successful continuation, fresh read or returned current observation replaces older page cursors; admitted input invalidates them. Empty, malformed, foreign and stale cursors remain rejected without silent refresh. None of these operations refunds read/recovery budgets or converts a browser cursor into a native computer cursor.

Saved catalogs without `browser_continue` keep legacy `browser_read(view?, query?, cursor?)`: omitted/null cursor starts a fresh read; a nonempty cursor continues its selection. Repeated view/query values must match the capture; changed filters are an explicit failure. Exact saved disjoint schemas from builds 231–233 migrate to this legacy flat contract when the new continuation tool is absent. Completed history preserves original arguments and names. Inventory remains separate: `browser_tabs.cursor` still accepts null or omission for a fresh inventory. Nullable compatibility never applies to required `browser_continue.cursor`, other fields or custom schemas. Schema validation enforces the offered form; the controller retains document, cursor and filter checks.

One task writes a leased tab at a time. Only eligible published rows with an exposed label receive typed action references. During continuation, a broker-minted immutable witness retains the original exposed row and target. A successful fresh read can corroborate that already published target in its full bounded native capture even if the selected view omits it. This requires a unique present node with byte-identical native action semantics, in the same binding, physical tab, known committed document, loader, generation and URL. Changed, missing, ignored or ambiguous nodes retire their references. Corroboration preserves the original exposure, capture deadline and FIFO age; it never authorizes an unexposed target. A previously prepared approval cannot follow a new corroboration revision. The original capture deadline is rechecked through the final input commit, and admitted input still consumes all references. Failed or unpublished reads cannot supply corroboration for a later fresh read.

The host freezes the reference's exact snapshot, row, role and exposed label before approval and retry accounting. Approval cannot silently move to a newer observation. Execution rechecks that frozen target, current identity, document generation/URL, connected physical node, unchanged role/label/value/link metadata, enabled state and obstruction. Admitted input consumes all current references before dispatch. A permit can be consumed once. An uncertain or timed-out mutation is not replayed; callers may inspect read-only state and report what remains unverified.

Turn completion, Stop and runtime shutdown revoke the turn lifetime before awaiting cleanup. A late opening closes its returned task-owned tab instead of publishing a binding. Existing user tabs survive release; cleanup never substitutes a same-title or same-URL tab. A task-created tab already closed by the user is recognized by its never-reused ID. Tool tabs keep a background rendering surface and can still be selected in the human UI. Task-owned pop-ups and new-window link activation are rejected so cleanup cannot orphan a page.

The same popup restriction applies to an existing human document after a browser tool attempts input on it. The guard remains through delayed page callbacks, Stop and task cleanup; a replacement document must commit before human popups work on that tab again. A reload or fresh document navigation provides that replacement; a SPA route change or failed navigation does not. A declined action leaves human popup behavior unchanged. This conservative document boundary preserves ordinary human login popups on untouched or replaced documents, and does not claim precise attribution of concurrent human and tool callbacks. A synchronous rejection reports that input was dispatched and must not be replayed; it does not prevent reading the retained page.

Full Access uses Computa's existing approval behavior; it does not remove host scope, stale-state or permit checks. Declined actions dispatch no input. Page content is untrusted data, not permission or new instructions. Model inference and app-control webviews never become tool targets, even when a title or URL resembles a human page.

The host derives conservative target restrictions from the submitted user request, never from model arguments or page text. An unambiguous explicit URL restricts the host and port; a recognized service restricts its allowed hosts, and an exact tab title is checked when choosing a tab. The controller applies those restrictions to inventory, binding, creation, navigation, exposed link destinations and current document publication. Unknown or ambiguous requests do not invent a target restriction. An explicit Chrome-only request excludes the built-in backend; a generic background-browser request can use it. A script-driven redirect can occur after an admitted press, but unrelated redirected content cannot be published as evidence for the restricted task.

Built-in browser failures participate in the runtime's unchanged-attempt budget. Three failures for the same normalized tool intent stop that turn before a fourth request can dispatch input. New `browser_continue` and legacy non-null `browser_read.cursor` calls share a continuation key; switching names, cursors or filters cannot reset it. A successful fresh read on the same native document does not clear this family; a successful continuation or host-verified new binding/committed document can. Mutation keys use native target identity and the intended operation/value, not opaque references, snapshots or row indices. Unknown or wrong-type references share a routing-only counter and cause no automatic capture. A successfully published current-reference input clears that routing counter; reads, rebinds and failed input do not. Other intent failures and outcome verification remain separate. A fresh user turn remains usable. This is a limit on unchanged failures, not a claim that arbitrary sites are compatible.

## Supported surface and validation

The initial backend reads main-frame light-DOM semantics and uses JavaScript semantic activation, rather than trusted OS pointer/keyboard events. Password values are excluded even when page-provided ARIA assigns a different role. Fill authority requires an actual editable input, textarea, select or contenteditable surface; an ARIA textbox role alone does not make an arbitrary element writable. Oversized labels/values disable action authority instead of comparing clipped text. Custom role attributes and their normalized lowercase token are limited to 100 UTF-8 bytes, with a character bound checked before encoding. Oversized roles become nonactionable generic metadata and mark semantic coverage incomplete, preserving useful observations of the remaining controls. Visible frame and shadow subtrees that this backend cannot inspect also mark source coverage incomplete; negative conclusions must not ignore that unread material. Sites requiring trusted input, unsupported frames, authentication, verification or other unavailable controls remain explicit compatibility boundaries.

Offline controller tests cover schema rejection, inventory pagination including oversized grapheme/control titles, issued binding IDs, leases, fresh snapshot consumption, navigation, event waits, cancellation races, requested-target restrictions and ownership-safe cleanup. Real isolated WebKit fixtures cover flight forms/results, private-world isolation, stale metadata, password protection, forged editable roles, readonly/inert controls, oversized/multibyte/lowercase-expanding roles, inference exclusion and background rendering. Production runtime fixtures separately exercise schema advertisement, active-turn checks, native approval/decline, late approval after Stop, mixed native/browser routing, repeated unchanged failures and shutdown. These describe the test coverage; final pass counts belong to the source-bound validation receipts.

The final 0.6.0 (37) native validation passed 404 selected tests with zero failures in 154.862 seconds, bound to 310 unchanged frozen input hashes. Runtime fixtures reject mixed or malformed tool definitions. The real-engine [workflow benchmark](HARNESS-WORKFLOW-BENCHMARK.md) configures the browser controller before thread creation, validates the combined native/browser schemas, and requires an accepted `thread/start` reply before continuing its actual editing/terminal/Git/localhost workflow with scripted inference. Its inert browser backend isolates startup acceptance from browser action proof; isolated WebKit and controller fixtures provide separate browser coverage.

Signed installed website-model tasks and public-site checks require their own receipts; offline tests or a synthetic United-style flight board do not establish access to a real booking or universal website compatibility. Installed website-model qualification uses separate source-bound receipts for each controlled task.
