# Native interface capability diagnostics

These experiments distinguish a model's unsupported-capability assumption from
an actual failed computer operation. They do not execute generated computer
actions or establish successful remote tab collection.

- `fixtures.ts`: four synthetic development and eight held-out next-step cases.
  Expected calls are scored independently; no expected action enters model input.
  No-action scores do not establish that an explanation is factual.
- `prompts.ts`: frozen experimental instruction candidates. The selected longer
  candidate regressed on held-out checks and **was not promoted**.
- `run.ts`: bounded, serial, localhost-only Responses diagnostics. Every request
  requires the sole loaded 4B model to be idle. Exact inherited policy content is
  reused from the baseline rollout, alongside all twelve dynamic tool schemas.
  This is a reconstructed prefix, not the original production wire request.
- `inspection-routes.ts`: a separate benchmark-only structured capability
  projection. Permission readiness identifies prerequisites, not a claim that a
  given window, remote desktop, or screenshot is accessible.
- `owned-runtime.ts`: launches the verified packaged App Server in an isolated
  home. A loopback gate verifies actual outgoing instructions, tools, inherited
  policy and task before forwarding bytes unchanged to LM Studio. Only recorded
  status/apps results are replayed; the first other call is recorded, then the
  owning turn is interrupted before any computer action can execute.
- `host-contract.ts`: rejected generic host-description experiment.
- `target-resolver.ts` / `resolver-run.ts`: rejected extra-model classification
  experiment; strict JSON validation, no generated actions dispatched.
- `explicit-app-mention.ts`: rejected deterministic mention-and-row-order
  experiment. A literal mention is not intent or permission. `mention-safety`
  runs six fresh, frozen cases with canonical native-style inventory rows.
  `mention` replays the old corpus, but all of those pairs are unchanged-input
  controls and cannot measure an annotation effect.
- `rejected-mention-native/`: unbuilt native candidate and exact withdrawn
  integration diff retained as evidence, outside production source discovery.

Use a **fresh empty mode-0700 output directory** for each run. Raw requests and
responses stay private, outside this repository. Never run model diagnostics in
parallel with Computa work or another inference test. No returned tool call is
dispatched. Inherited policy is neither rewritten nor removed.

```sh
bun test Benchmarks/CapabilityRouting
bun Benchmarks/CapabilityRouting/run.ts development PRIVATE_OUTPUT BASELINE_ROLLOUT
bun Benchmarks/CapabilityRouting/run.ts holdout PRIVATE_OUTPUT BASELINE_ROLLOUT baseline,boundary DEVELOPMENT_SUMMARY
bun Benchmarks/CapabilityRouting/run.ts recorded PRIVATE_OUTPUT BASELINE_ROLLOUT baseline,boundary
bun Benchmarks/CapabilityRouting/run.ts inspection PRIVATE_OUTPUT BASELINE_ROLLOUT
bun Benchmarks/CapabilityRouting/run.ts contract PRIVATE_OUTPUT BASELINE_ROLLOUT
bun Benchmarks/CapabilityRouting/run.ts mention-safety PRIVATE_OUTPUT BASELINE_ROLLOUT
bun Benchmarks/CapabilityRouting/owned-runtime.ts PRIVATE_OUTPUT BASELINE_ROLLOUT baseline
bun Benchmarks/CapabilityRouting/owned-runtime.ts PRIVATE_OUTPUT BASELINE_ROLLOUT capability_header
bun Benchmarks/CapabilityRouting/owned-runtime.ts PRIVATE_OUTPUT BASELINE_ROLLOUT explicit_mention
```

The holdout command requires the exact completed development audit with matching
corpus, candidate and baseline hashes, plus one previously tested candidate.
Recorded mode performs three paired repeats on the recorded two-call prefix; it
does not dispatch actions or count a proposed open as a completed task.

`run.ts` uses temperature 0.1 and a 2,048-token output cap, excludes original
reasoning/commentary and the built-in request-user-input tool, and bypasses the
owned App Server loop. Permission-negative fixtures say `denied`, unlike the
production `not-granted` value; do not claim permission-path parity. Synthetic
AX is contract-shaped rather than generated by the native formatter. These
limitations are explicit because the simplified replay did not reproduce the
actual live refusal.

`inspection` reuses the twelve already-seen fixtures: it is a retrospective
regression replay, not new held-out evidence. Five cases include an apps receipt;
the other seven are unchanged-input controls. The capability header is the sole
intervention, and is not appended to system instructions.

The owned-runtime gate accounts narrowly for the pinned App Server serializer
omitting length/range keywords from three schemas. Submitted schemas remain
unchanged, native validation remains authoritative, and unexpected schema
differences still stop before inference. Its isolated home and loopback gate
are not an OS-wide network sandbox. Recorded permissions are not fresh checks.
An intentional interrupted next-action trial is not a completed task. Report
action latency from protocol timestamps, not `turnMS`, which includes shutdown.

Results, exclusions and manual factual audits are recorded in
`../SCREEN-SHARING-2026-09-25.md`. No success rate from these next-step checks is a
computer-use accuracy or end-to-end task-completion rate.
