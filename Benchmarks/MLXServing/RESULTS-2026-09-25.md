# Direct MLX-VLM 0.7.1 transport baseline

The installed official server was tested directly on loopback with the existing
Qwen3.5-4B MLX 4-bit weights. One server, one sequence, 16,384 context limit,
512-token prefill chunks, vision cache capacity 1, APC disabled. Original HeyDash
instructions and inherited policy were preserved. No real tool was executed.

All four **strict gates failed**. This is not a successful app migration gate.

| Primitive | Measured result | Wall time |
| --- | --- | ---: |
| Exact text | 4,096 reasoning deltas, no visible-text deltas; final response incorrectly exposed that unfinished reasoning as an answer and reported completed | 49.394 s |
| Function call | Exactly one read-only function, matching call ID, arguments-done and output-item-done lifecycle passed | 1.369 s |
| Token continuation | Exact returned token semantically correct, but visible deltas contained two leading newlines absent from the final message | 1.349 s |
| Image function call | Correct read-only fixture call and lifecycle passed | 1.678 s |
| Image continuation | Actual image-bearing tool-result body counted and hashed; correct left/right statuses, but fenced JSON violated the strict format and delta/final whitespace differed | 4.719 s |
| Cancel after visible token | Client disconnected at 0.469 s; metrics subsequently reported no in-flight request or queued request | 0.469 s |
| Following request | Completed with correct semantic marker; same delta/final whitespace mismatch | 3.705 s |

The cancellation request alone disabled thinking to reach a visible token
promptly. It was cancelled before any completed event. The following request
restored medium reasoning. Cancellation usage is unavailable, not zero.

## Source-correlated incompatibilities

Installed `mlx_vlm/server/responses_state.py` reparses final generated text in
`_response_output_items_from_text()` without forwarding `starts_in_thinking`.
The streaming parser does know the prompt already opened a thinking block.
Without a generated closing token, the final parser consequently treats text
as an answer despite no visible-text deltas. Separately, final parsing strips
whitespace while streaming emits it unchanged.

Installed `mlx_vlm/server/openai.py` retains a `length` finish reason in its
metrics but constructs a completed response unconditionally. Its token usage
contains input/output/total counts but no reasoning-token breakdown. Do not
report missing reasoning usage as measured zero.

These are server-compatibility findings, separate from the model's decision to
spend its budget reasoning or to format JSON in a fence. A compatible adapter
must preserve the stream's actual content/reasoning distinction and surface
incomplete generation without presenting reasoning as a final answer.

Private raw evidence remains in
`/tmp/heydash-mlx-responses-20260925.nSn93s`. Its `summary.json` records source,
request, image and event hashes; raw requests and events are mode 0600. No raw
reasoning or private screenshots are committed here. The final metrics showed
six completed requests, one cancelled stream, no active request and no queue.

The parser's CRLF-split regression test was added **after** this run; the frozen
source hashes in the evidence identify the exact implementation that ran.
