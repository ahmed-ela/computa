# Synthetic AX extraction diagnostic — 2026-09-25

These are bounded diagnostics on the already-loaded local Qwen3.5-4B MLX 4-bit
instance, using loopback Responses requests, synthetic observations, temperature
0.1, and no tools or private data. They are not App Server or computer-use gates.
No complete 16-case benchmark or general reliability ranking was established.

## Repeated-ancestry experiment

An initial 768-token run exhausted reasoning without final answers and was
stopped. Status labels were then made explicit (`Arrives Tuesday` / `Delivered
Friday`) and the cap raised to 2,048. That second batch stopped after three of
16 planned requests:

| Case | Outcome | Seconds | Reasoning / total output tokens |
| --- | --- | ---: | ---: |
| Full, ancestry retained | Correct status | 9.495 | 868 / 872 |
| Full, ancestry removed | Wrong card's status | 15.760 | 888 / 892 |
| Missing requested status, ancestry retained | No final answer | 39.845 | 2,047 / 2,047 |

The third row is a bounded no-answer failure, not an answered-but-wrong
extraction. The remaining 13 requests did not run. The old runner did not save
a partial summary; the individual result artifacts remain preserved in
`/tmp/heydash-ax-association-v2-20260925.GA2LTO/`.

## Reasoning-control probe

A separate request with Responses `reasoning.effort=none` echoed that setting,
but still generated 255 reasoning tokens, no final answer, at a 256-token cap.
The documented native `/api/v1/chat` request with `reasoning=off` returned HTTP
400: the loaded model does not expose reasoning configuration. Therefore neither
the echo nor the generic API option establishes working control for this model.
No persistent configuration, model template, or vendor code was modified.

Artifacts: `/tmp/heydash-reasoning-none-20260925.OmhtNz/`.
[LM Studio native chat reference](https://lmstudio.ai/docs/developer/rest/chat)
documents that unsupported reasoning settings can error.

## Limits and reporting safeguards

Every question targets Order A, always first and value-backed, while Order B's
status is title-backed. Fixed ordering, no repetitions, a tiny fixture set, and
prompt revisions prohibit general accuracy, reliability, or latency claims.
Counterbalance target order and title/value encoding before a broader benchmark.

The revised batch runner validates all fixtures before model access, distinguishes
answered-correct, answered-wrong, no-final-answer, server-error, and transport-error,
and atomically saves partial summaries with attempted and unrun counts. Nonanswers
are not given an answered-extraction correctness score. A malformed-input check
saved `state=stopped`, `fixtures_validated=false`, zero attempted, and 16 unrun
without model access (`/tmp/heydash-ax-runner-invalid-20260925.JMDN0V/`). Bun
transpilation passed. The revised full batch has not been run to completion.
